# 判定: 修正して再検証

| 評価軸 | regress | ux | 優位 |
|---|---|---|---|
| 要求適合 | 回帰、公式 needs 契約、読み取り専用性を検証 | 実画面の導線と状態理解を検証 | 同等 |
| 正確さ | 実行結果、exit code、`ok:false` 検査、差分照合が明示的 | `verify=pass` / `ok:true` と未解決指摘が矛盾 | regress |
| 完成度 | 対象・隣接・全テストまで成功を報告 | 設計書との最終状態不一致と README 同期テスト不足が未解決 | regress |
| 契約・不変条件 | 公式 needs 契約逸脱、done 不変条件違反なし | 読み取り専用 UI で違反なし | 同等 |
| UX解決性 | 回帰保護は十分だが実利用上の指摘は扱わない | 未解決UX問題を発見 | ux |

`regress` はテスト失敗、terminal `ok:false`、公式契約逸脱、done 不変条件違反を報告していない。一方、`ux` には未解決指摘が残るため、明示された判定規則により完了不可であり、修正後に回帰・UXを再検証すべきである。UX報告自身の合格表示はこの規則と矛盾するため採用しない。
